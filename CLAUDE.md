## Commands

```bash
npm run dev     # dev server on :3000 (Turbopack)
npm run build   # production build (Turbopack)
npm start       # serve the production build
npm run lint    # eslint (flat config)
```

There is no test setup in this repo yet. `next lint` was removed in Next 16 — run `eslint` directly, and note that `next build` no longer lints.

`next dev` writes its PID/port/URL to `.next/dev/lock`; a second `next dev` prints the existing server's URL instead of starting a duplicate. It also forwards browser console errors/warnings to the terminal, so client-side failures are visible without opening the browser.

## Stack and conventions

Next.js 16.3.3 (App Router only, no `pages/`), React 19.2.8, TypeScript strict, Tailwind CSS v4.

- **Routing**: everything lives under `app/`. `app/layout.tsx` is the root layout, `app/page.tsx` the index route.
- **Typed routes**: Next generates `.next/types/routes.d.ts` with global `PageProps<"/route">` and `LayoutProps<"/route">` types keyed by literal route strings (see `app/layout.tsx` using `LayoutProps<"/">`). Use these instead of hand-written prop types; the file is regenerated by `next dev`/`next build`, so a new route's type only exists after the server has seen it.
- **Async request APIs**: `params` and `searchParams` are Promises — `await` them.
- **Tailwind v4**: configured entirely in CSS. There is no `tailwind.config.js`; theme tokens live in the `@theme inline` block in `app/globals.css`, wired to `:root` CSS variables (`--background`, `--foreground`) that flip under `prefers-color-scheme: dark`. Fonts come from `next/font/google` in the root layout, exposed as `--font-geist-sans` / `--font-geist-mono` and mapped to `--font-sans` / `--font-mono`.
- **Imports**: `@/*` resolves to the repo root (e.g. `@/app/...`).
